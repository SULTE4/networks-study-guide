IPv4 rules

  • Subnets = 2H, where H is the bits borrowed.
  • Hosts = 2h - 2, where h is the host bits left.
  • The 2 removed are the network (host bits all 0) and broadcast (host bits all 1).
  • ANDing compares address and mask bit by bit.
  • Unicast is one host, broadcast is all on the network, multicast is a group.
  • Only a router stops broadcasts.
  • VLSM: largest first, /30 for a router link.
  • IANA gives blocks to 5 RIRs, then ISPs.
  • Clients use DHCP. Servers and printers use static addresses.

Reading IPv6

  • 128 bits, 8 hextets, each 16 bits. /64 for LANs.
  • Rule 1: drop leading zeros only.
  • Rule 2: :: replaces one run of zero hextets, once only.
2 or 3...GUA (2000::/3), like public
fe80...Link-local, one link only, every interface has one
fc or fd...Unique local, like private
ff...Multicast. ff02::1 all nodes, ff02::2 all routers
::1 / ::Loopback / unspecified

IPv6 has no broadcast and no ARP. ICMPv6 Neighbor Discovery replaces ARP.

EUI-64 and coexistence

  1. Split the MAC in half.
  2. Insert ff:fe in the middle.
  3. Flip the 7th bit: 00 becomes 02.

No ff:fe in the middle means the ID is random.

Coexistence: dual stack runs both. Tunneling puts IPv6 inside IPv4. NAT64 translates.

UDP is used for: live voice and video, simple request and reply (DNS, DHCP), and applications that handle reliability themselves (TFTP, SNMP).

TCP numbers and flags

  • Open: SYN, SYN-ACK, ACK. Close: FIN, ACK, FIN, ACK.
  • Sequence number: reassembles data in order.
  • ACK number = next byte expected = sequence + bytes received.
  • Window: bytes accepted at one time.
  • RST resets on error or timeout.
  • MSS 1460 = 1500 MTU - 20 IP - 20 TCP.
  • Socket = IP + port.
  • Ports: well-known 0-1023, registered 1024-49151, dynamic 49152-65535.

Upper layers

  • OSI application, presentation and session together form the TCP/IP application layer.
  • Presentation: formats, compresses, encrypts.
  • Session: creates and maintains dialogs, restarts interrupted ones.

DHCP

  • Gives IP, mask, gateway and DNS server, as a lease from a pool.
  • Discover: broadcast from 0.0.0.0 to 255.255.255.255.
  • Offer: server offers a lease.
  • Request: broadcast so other servers know they lost.
  • Ack: confirmed. NAK if the offer is no longer valid.
  • Other network: router as relay, ip helper-address.

Web

  • HTTP uses TCP because it needs reliable delivery. It is stateless, so sites use cookies.
  • GET requests, POST sends, PUT uploads, DELETE removes.
  • 200 OK, 301 moved, 403 denied, 404 not found, 500 server error.
  • HTTPS (TLS): encryption, authentication with a certificate, integrity.

Email

  • SMTP sends. If the server is busy, it spools and retries.
  • POP3 downloads, deleted from the server by default. Good for one device.
  • IMAP stays on the server and syncs. Good for phone + laptop.

Files and remote access

  • FTP: 21 control, 20 data, login needed.
  • TFTP: no login, no listing, for IOS images and configs.
  • SMB: file and printer sharing. It starts, authenticates and ends sessions. The connection stays open, so remote files look local.
  • SSH encrypts logins and data. Telnet sends them in plain text. Use SSH to manage devices.
  • FTP and TFTP are unencrypted. Use SFTP (over SSH, port 22).
