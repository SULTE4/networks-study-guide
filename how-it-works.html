Who does what

Think of a network as a postal system. Data is the letter, and each protocol is one worker with one job.

The words everything else uses

HostAny device with an address: laptop, phone, server.
IP addressThe device's postal address. It says which network and which device.
MAC addressThe number fixed to the network card. It is used only to reach the next device on the same link.
PortThe number of a program on the device, like an apartment number in a building.
SwitchConnects devices inside one network.
RouterConnects different networks to each other.
ProtocolA set of agreed rules, so two devices understand each other.
TCP and UDP: you have it right. UDP sends and forgets: no acknowledgment, no resend. TCP confirms what arrived and resends what did not. One addition: UDP is not "bad". It is chosen when speed matters more, because a late video frame is useless anyway.
DHCP: a small correction. DHCP does not identify who is who. Its job is to give a device its address, like reception handing you a room number when you arrive. The "who is who" jobs belong to DNS (which IP has this name?) and ARP (which MAC has this IP?).

Follow one click from start to finish

You connect a laptop to Wi-Fi and open www.example.com. This one story uses almost everything in the course, so read it twice.

  1. "I have no address." DHCP gives the laptop an IP (192.168.1.20), a mask, the gateway (192.168.1.1) and a DNS server.
  2. "I only know a name." DNS answers: www.example.com is 203.0.113.10.
  3. "Is this address near me?" The laptop compares the address with its own network using the mask. It is another network, so the data must go to the default gateway.
  4. "What is the gateway's MAC?" ARP shouts on the local network: "who has 192.168.1.1?" The router answers with its MAC.
  5. "Are you ready to talk?" TCP does its handshake with the server on port 443, which means the web server program.
  6. "Carry this across the Internet." Each router reads the destination IP and passes the packet to the next router. The IPs stay the same the whole way, but the MACs are replaced at every router.
  7. "Here is the page." The HTTPS reply comes back to the laptop, the laptop's port number picks the browser, and you see the page.

Every section below is a close look at one step of this story.

The key idea: IP finds the device across the world. MAC finds the next device on this link. Port finds the program. IP stays the same on the way, and MAC changes at every router.

THE CALCULATION TASKS

One idea behind every calculation

The whole idea: an IP address is 32 bits with a line drawn through it. Left of the line is the network, right of the line is the host. The prefix (/26) says where the line is. Every task is just finding what that line does.

Start from zero: the four things you need

1. Binary in one minute

Each octet (one of the four numbers in an IP) is 8 bits. Each bit position has a fixed value. Add the values where the bit is 1.

Position1st2nd3rd4th5th6th7th8th
Value1286432168421

Example: 11100000 has the first three bits on, so 128 + 64 + 32 = 224.

2. What /27 means

It means the first 27 bits are the network and the remaining 5 are hosts. Those 27 bits are written as 1s in the mask, and the rest as 0s. So /27 is the mask 255.255.255.224. The two ways of writing it say the same thing.

3. Find the octet where the line falls

Each octet is 8 bits, so take away 8s from the prefix. For /27: 8 + 8 + 8 = 24, and 3 bits are left. So the line is inside the 4th octet, 3 bits in. For /21: 8 + 8 = 16, and 5 bits are left, so it is inside the 3rd octet, 5 bits in.

4. The method, always the same 4 steps

  1. Find the octet where the line falls, and its block size.
  2. List multiples of the block in that octet, and find the one at or just below your number. That is the network value.
  3. Add the block and subtract 1. That is the broadcast value.
  4. Octets left of the line are copied. Octets right of the line are 0 in the network and 255 in the broadcast.

Why the method works

Why there is a block size

The numbers on the left of the line are fixed. Subnets only change by the last network bit, so its value is the step between subnets. /26 ends in 11000000, and the last 1 has weight 64, so subnets go 0, 64, 128, 192. A quick shortcut gives the same number: 256 - 192 = 64.

Why the network is a multiple of the block

The network address means all host bits are 0. Clearing the bits on the right is the same as rounding down to a multiple of the block. So 200 with block 32 rounds down to 192.

Why the broadcast is one before the next

The broadcast means all host bits are 1, which is the very last address of the block. One step further is already the next subnet.

Why hosts have minus 2 and subnets do not

Inside each subnet, two addresses are taken: network (all 0s) and broadcast (all 1s). So Hosts = 2h - 2. The subnets themselves are all usable, so Subnets = 2H. Here h is the host bits left, and H is the bits you borrowed.

Why borrowing trades hosts for subnets

Moving the line right by one bit doubles the subnets and halves the addresses in each. That is the only trade there is. "Most subnets" always means: use the fewest host bits that still fit.

Why VLSM goes largest first

A block must start at a multiple of its own size. Big blocks are the pickiest, so place them first and the small ones always fit after. This avoids waste: a router link needs 2 addresses, so give it a /30 and not a /27.

Why IPv6 is the same but easier

The line for a LAN is at /64. Your bits are between the given prefix and /64, so subnets = 2(64 - prefix). Each hex digit is 4 bits, so count in hex (9, a, b ... f, 10). There is no minus 2, because IPv6 has no broadcast.

Move the line and watch

Drag the slider and see what changes. This is the fastest way to feel why the method works.

Six examples, every step shown

Example 1: the line is in the last octet

Task: find the network, broadcast and usable range of 192.168.1.100 /27.

  1. 27 = 24 + 3, so the line is 3 bits into the 4th octet. From the table: block 32.
  2. Multiples of 32: 0, 32, 64, 96, 128. The number 100 is between 96 and 128, so the network value is 96.
  3. 96 + 32 - 1 = 127 is the broadcast value.
  4. The first three octets are left of the line, so copy them.

Network 192.168.1.96, broadcast 192.168.1.127, usable 192.168.1.97 to 192.168.1.126, hosts 25 - 2 = 30.

Example 2: the line is in the 3rd octet (the one people get wrong)

Task: the same, for 10.4.77.200 /21.

  1. 21 = 16 + 5, so the line is 5 bits into the 3rd octet. Block 8. Work on the number 77, and ignore the 200 for now.
  2. Multiples of 8: ... 64, 72, 80. So 77 belongs to 72.
  3. 72 + 8 - 1 = 79.
  4. The 4th octet is right of the line: 0 in the network, 255 in the broadcast. The 200 never matters.

Network 10.4.72.0, broadcast 10.4.79.255, usable 10.4.72.1 to 10.4.79.254. Host bits = 32 - 21 = 11, so hosts = 211 - 2 = 2046.

Example 3: choose a mask for a number of hosts

Task: smallest subnet for at least 50 hosts.

  1. Try powers of 2, minus 2. With 5 host bits: 32 - 2 = 30, too few. With 6 host bits: 64 - 2 = 62, enough.
  2. Prefix = 32 - 6 = /26. The line is 2 bits into the 4th octet, so the mask value is 192.

/26, mask 255.255.255.192, 62 usable hosts.

  2. New prefix = 24 + 2 = /26. Block 64.

The mistakes that lose marks

  • Using the 4th octet when the line is in the 3rd. Always find the octet first.
  • Forgetting - 2 for hosts, or wrongly using - 2 for subnets.
  • Giving the network address or broadcast as a usable address.
  • In VLSM, starting with the small networks. Always largest first.
  • Choosing 2h without - 2. A subnet for 30 hosts fits in 5 bits, but one for 31 hosts needs 6.

PART 2

Addressing and services

IPv4 addressing

Role: give every device a logical address, and group devices into networks.

IN PLAIN WORDS

An IP address works like street + house number. In 192.168.1.20 /24, the street is 192.168.1 and the house is 20. Houses on one street can reach each other directly. To reach another street, you must go through a router.

How a computer does this (ANDing). Line up the address and the mask. A result bit is 1 only if both bits are 1. For 192.168.1.100 /27, the last octet is:

address  100 = 01100100
mask     224 = 11100000
AND          = 01100000 = 96

The result is 96, the same answer the block method gives. Block size is simply the fast way to do ANDing in your head.

Why subnet? Picture 1,000 devices in one network. When any device sends a broadcast, the other 999 must read it. Split them into groups with a router between, and each broadcast stays inside its group.

Spot the special addresses. If a PC shows 169.254.x.x, it asked for DHCP and nobody answered. Private addresses like 192.168.x.x are used inside your home or company, and the router swaps them for a public address when going to the Internet. That swap is NAT.

Why subnet at all? Broadcasts reach everyone in a network, and too many slow it down. Routers stop broadcasts, so smaller subnets mean less traffic, better security between groups, and fewer devices hit by a problem.

ANDing is how a device finds the network part: address AND mask, bit by bit.

IPv6

Role: solve the shortage of IPv4 addresses with 128 bits, and remove the need for NAT.

IN PLAIN WORDS

IPv4 has about 4.3 billion addresses and the world used them up. IPv6 is the bigger replacement. It is written as 8 groups called hextets. Each has 4 hex digits, which is 16 bits, and 8 x 16 = 128.

Shortening, step by step

Full:      2001:0db8:0000:0000:00a0:0000:0000:0001
Rule 1:    2001:db8:0:0:a0:0:0:1
Rule 2:    2001:db8::a0:0:0:1

There are two runs of zeros here, and :: may appear only once, or nobody could tell how many zeros each one hides. Use it on the longest run. If they are equal, use the first.

Know the type from the first digits

Starts with 2 or 3: global (public). fe80: link-local. fc or fd: unique local (private). ff: multicast.

Read one address

2001:db8:acad:1::10/64 has three parts: 2001:db8:acad is the prefix from the ISP (/48), 1 is your subnet ID, and ::10 is the interface ID, which is the host.

How a host gets an address

The host asks: "Router, what network is this?" (Router Solicitation). The router replies with a Router Advertisement containing the prefix and telling the host which method to use. With SLAAC, the host builds its own address from that prefix. Nobody keeps a list. Stateful DHCPv6 is like DHCP in IPv4: a server gives the address and remembers it.

EUI-64 example

MAC:          00:1a:2b:3c:4d:5e
Split, add:   00:1a:2b:ff:fe:3c:4d:5e
First byte:   00 = 00000000
Flip 7th bit: 00000010 = 02
Result:       021a:2bff:fe3c:4d5e

Living together: dual stack runs both, tunneling puts IPv6 inside IPv4, and translation (NAT64) converts between them.

Writing it: rule 1, drop leading zeros in a hextet. Rule 2, one :: replaces one run of zero hextets, used only once.

GUA 2000::/3Like a public address. Starts with 2 or 3
LLA fe80::/10One link only, every interface must have one, never routed
ULA fc00::/7Like private addresses, local use
Multicast ff00::/8Replaces broadcast. ff02::1 all nodes, ff02::2 all routers
AnycastSame address on many devices, you reach the nearest

Parts of a GUA: global routing prefix (from the ISP) + subnet ID (yours) + interface ID (the host).

Getting an address: the router's RA suggests one of three. SLAAC: everything from the RA. SLAAC + stateless DHCPv6: address from the RA, DNS from the server. Stateful DHCPv6: address from the server. In all three, the gateway is the router's LLA.

EUI-64: split the MAC, insert ff:fe, flip the 7th bit. Otherwise the interface ID is random.

Remember: no broadcast in IPv6. ipv6 unicast-routing comes first, or the router will not forward or send RAs.

Transport layer

Role: deliver data between applications. IP only reaches the device, and it guarantees nothing, so transport is where reliability can be added.

IN PLAIN WORDS

TCP is a phone call. You connect first, the other side confirms what it heard, and you repeat what was missed. UDP is a postcard. You send it and hope. Postcards are quicker, and fine when a lost one does not matter.

Ports: one laptop, many conversations

Your laptop opens two tabs on the same site. Both go to server port 443, but the laptop picks a different temporary source port for each one, say 50001 and 50002. Replies come back with the ports swapped, so each reply reaches the right tab. The socket pair is the four values together: source IP and port, destination IP and port.

The handshake with numbers

Client: SYN      seq=100
Server: SYN-ACK  seq=300  ack=101
Client: ACK      seq=101  ack=301

Each side picks a starting number, and each side confirms the other's number + 1. Three messages are needed because both directions must be confirmed.

What happens when a segment is lost

The sender sends three segments of 500 bytes each, starting at 1001, 1501 and 2001. The middle one is lost.

  1. The first arrives, so the receiver says ACK 1501: "send me byte 1501 next".
  2. The third arrives, but 1501 is still missing, so the receiver keeps saying ACK 1501.
  3. The sender resends only the segment at 1501.
  4. Now everything up to byte 2500 is here, so the receiver says ACK 2501.

Flow control: the window size is how many bytes may be sent before waiting for an ACK. A busy receiver makes the window smaller to slow the sender down.

Reading netstat: SYN_RECEIVED means the server got a SYN and is waiting for the final ACK. In a SYN flood, the attacker never sends that ACK, so thousands pile up.

Its jobs: track conversations, split data into segments and rebuild it, and identify applications by port.

Open: SYN, SYN-ACK, ACK. It proves both sides exist and are ready. Close: FIN, ACK, FIN, ACK. RST resets on error.

ACK number = first byte + bytes received. It means "send me this byte next". Sequence 1001 with 500 bytes gives ACK 1501.

Remember: DHCP must use UDP, because a device with no IP cannot do a handshake.

Application layer

Role: the services people actually use. Each protocol is one job.

IN PLAIN WORDS

DHCP as a conversation

Discover"Any DHCP server there? I have no address." It goes to everyone, because the client does not know who the server is.
Offer"You can use 192.168.1.20 for 24 hours."
Request"I accept that one." Also to everyone, so other servers can take back their offers.
Ack"Confirmed. Here are your mask, gateway and DNS server."

The address is only borrowed. Before the lease ends, the client renews it. If the client leaves, the address returns to the pool for someone else.

DNS as a chain of questions

You want www.example.com. Your DNS server asks a root server, which says "ask the .com servers". The .com server says "ask example.com's name server". That one gives the IP. Your DNS server caches the answer, so the next person gets it at once.

Email with two devices

You read mail on a phone and a laptop. With IMAP, mail stays on the server, so both show the same inbox. With POP3, the first device downloads the mail and removes it, so the other sees nothing. SMTP is only for sending.

Ports, grouped so they stick

Web: 80 plain, 443 secure. Remote login: 22 secure, 23 insecure. Email: 25 sends, 110 downloads, 143 syncs. Files: FTP 20 and 21, TFTP 69. Network helpers: DNS 53, DHCP 67 and 68.

Upper layers: Application, Presentation (format, compress, encrypt) and Session (keep the dialog going) join into one TCP/IP layer.

DHCP is DORA: Discover (broadcast, from 0.0.0.0), Offer, Request (broadcast, so other servers know they lost), Ack. The address is a lease for a limited time.

DNS order: root, then top-level (.com), then the domain. Records: A (IPv4), AAAA (IPv6), MX (mail server), NS (name server), CNAME (alias). Test with nslookup.

HTTP is stateless, so sites use cookies. GET asks, POST sends. 200 OK, 301 moved, 403 denied, 404 not found, 500 server error. HTTPS adds TLS: encryption, a certificate proving identity, and integrity.

Mail: SMTP sends. POP3 downloads and deletes from the server. IMAP keeps mail on the server, synced on every device.

Files: FTP has control on 21 and data on 20. TFTP is simple with no login, for IOS images. SMB shares folders and printers.

THE FOUNDATION

The foundations

Network layer

Role: move packets from the source device to the destination device, even across many networks.

IN PLAIN WORDS

The network layer is the long-distance part of the trip. Think of the IP as the final destination on your ticket, and each MAC as just the next bus stop.

Local or remote?

PC 192.168.1.10 /24 wants to reach 192.168.1.50. The street is the same, so it sends directly. To reach 10.0.0.5, the street is different, so it sends to the gateway.

What changes on the way

PC to router R1, to router R2, to the server:

HopSource MACDest MACSource IPDest IP
PC to R1PCR1PCServer
R1 to R2R1R2PCServer
R2 to ServerR2ServerPCServer

The two IP columns never change. The two MAC columns change on every hop. Exams ask this often.

TTL: a packet starts with a number, and each router subtracts 1. At 0 the router drops it and reports back with ICMP. This stops packets from circling forever, and traceroute uses it to discover each router on the path.

IP is connectionless (no setup), best effort (no guarantee, no resend) and media independent (copper, fiber or radio). This is why TCP is needed above it.

Each host decides: is the destination local or remote? It compares using its own IP and mask. Local goes direct, remote goes to the default gateway.

Which MAC goes on the frame? Same network: the destination's MAC. Remote network: the gateway's MAC. ARP finds it, and the ARP table stores it.

Router's table: directly connected (C, L), remote (static S or dynamic O, D), and default route (S*). Static is manual, dynamic adapts by itself.

Header: TTL is a hop count, and at zero the packet is dropped. The Protocol field names the next level (TCP, UDP, ICMP). IPv6's header is simplified at 40 bytes, Hop Limit replaces TTL, and routers do not fragment IPv6.

Router setup: hostname, enable secret, line console 0, line vty 0 4, service password-encryption, banner motd, copy running-config startup-config. Interface: ip address and no shutdown.

Remember: no gateway or a wrong gateway means traffic cannot leave the LAN. A switch needs ip default-gateway only to be managed from another network.

Data link and switching

Role: deliver a frame from one network card to the next on the same link, and reject corrupted frames.

IN PLAIN WORDS

How a switch learns, in four moments

  1. The MAC table is empty. PC A on port 1 sends a frame to PC C.
  2. The switch learns: "A is on port 1" (it reads the source MAC).
  3. It does not know where C is, so it floods the frame out of every other port.
  4. C replies from port 3. The switch learns "C is on port 3", and from now on A and C go straight to each other.

Half-duplex is a walkie-talkie: one talks at a time. Full-duplex is a phone call: both talk at once. CSMA means "listen before you talk". Wired Ethernet /CD notices a collision and retries. Wi-Fi /CA tries to avoid collisions, because a radio cannot hear one while it is sending.

FCS is a check value. The sender calculates it from the frame, and the receiver calculates it again. If the two differ, the frame is thrown away.

Two sublayers: LLC talks up to the software (802.2). MAC handles encapsulation and access to the media.

Frame: 64 to 1518 bytes. Under 64 is a "runt" and is dropped. The FCS trailer detects errors.

MAC address: 48 bits, 12 hex digits. First half is the vendor (OUI). Broadcast is FF-FF-FF-FF-FF-FF. Multicast starts 01-00-5E (IPv4) or 33-33 (IPv6). The source MAC is always unicast.

A switch does two things: learn the source MAC and its port, then forward by the destination MAC. Unknown or broadcast: flood out all ports except the incoming one. Entries last about 5 minutes.

Sharing the medium: half-duplex is one at a time, full-duplex is both. CSMA/CD detects collisions (old Ethernet), and CSMA/CA avoids them (Wi-Fi).

Topologies: physical shows cables, logical shows addressing. LAN: star, extended star, bus, ring. WAN: point-to-point, hub and spoke, mesh.

Remember: learn from the source, forward on the destination.

Physical layer

Role: turn a frame into real signals on a cable or in the air.

IN PLAIN WORDS

Think of a road. Bandwidth is how wide the road is. Throughput is the traffic that really passes. Goodput counts only the passengers, not the weight of the vehicles. Latency is how long the trip takes. For example, a 100 Mb/s link may carry 80 Mb/s in practice, and 70 Mb/s of that is your real data.

Three problems of copper: attenuation is a voice fading with distance. EMI/RFI is noise from nearby machines and radios. Crosstalk is hearing the wire next to you.

Choosing a medium in a question: near heavy electrical noise, or between buildings: fiber. Very long distance: single-mode fiber. A normal office under 100 m: UTP. Moving users: wireless.

Signals: electrical on copper, light on fiber, radio on wireless. Encoding makes the bit pattern, signaling represents it physically.

Speed words: bandwidth is capacity. Throughput is what actually passes. Goodput is the usable data (throughput - overhead). Latency is delay.

Copper: cheap and common. Its limits are attenuation (weaker with distance), EMI/RFI and crosstalk. UTP max is 100 m, and twisting the pairs cancels interference. STP adds shielding.

Fiber: longest and fastest, completely immune to EMI, but costly. Single-mode: tiny core, laser, long distance. Multimode: larger core, LED, up to 550 m.

Wi-Fi: an AP connects wireless users to the wired network. 2.4 GHz: longer range but crowded, use channels 1, 6, 11. 5 GHz: less crowded, shorter range.

Remember: fiber is immune to EMI. UTP stops at 100 m.

Networks and Cisco IOS

Role: the vocabulary of networks, and how to talk to a Cisco device.

IN PLAIN WORDS

LAN is the roads inside your neighborhood. WAN is the highways between cities. Packet switching means data is cut into pieces that can take different roads, so one broken road does not stop the trip. That is fault tolerance.

The Cisco prompt tells you where you are

Switch>                     can only look
Switch> enable
Switch#                     can see everything
Switch# configure terminal
Switch(config)#             changes the whole device
Switch(config)# interface g0/1
Switch(config-if)#          changes one port

Running-config is like a document you are typing, and startup-config is the saved file. If power goes off, everything unsaved is gone.

Devices: end devices start or receive data. Intermediary devices (switches, routers, APs, firewalls) connect them and manage the flow.

Peer-to-peer: easy and cheap, but not secure or scalable, so only for very small networks.

LAN covers a small area, run by one organization, fast. WAN covers a wide area, run by providers, usually slower. Intranet is private, extranet lets outside partners in.

A reliable network has four qualities: fault tolerance (several paths, packet switching), scalability, QoS (voice and video first), and security (confidentiality, integrity, availability).

Trends: BYOD, online collaboration, video, cloud (public, private, hybrid, custom), smart homes, powerline, wireless broadband.

IOS access: console (physical), SSH (secure remote), Telnet (insecure remote).

Modes: > user EXEC, enable to # privileged, configure terminal to (config)#, then interface or line. exit goes back one, end goes to privileged.

Two config files: running-config is in RAM and active now. startup-config is in NVRAM and used at boot.

Remember: changes are lost on reboot until copy running-config startup-config.

Which cable connects what

Easy rule: straight-through only when exactly one end is a switch. Everything else is crossover.

Why this rule exists: a wire pair must connect one side's sending pins to the other side's receiving pins. PCs and routers send on pins 1 and 2. Switches send on pins 3 and 6. So a PC and a switch already match, and a straight cable works. Two devices of the same kind would send into each other, so the wires must cross.

STUDY AFTER THE REST

Network security

Network security

Role: keep data private, unchanged and available, by stopping people and programs that should not get in.

IN PLAIN WORDS

Take your grades on a student portal. Confidentiality: only you can see them. Integrity: nobody can change 70 to 30. Availability: the portal works when you need it.

Take a house. The threat is that burglars exist. The vulnerability is the unlocked window. The attack is the burglar climbing in.

Three goals (CIA): confidentiality (only the right people can read it), integrity (nobody changed it), availability (it works when needed).

Three words people mix up: a threat is what could harm you, a vulnerability is the weak spot, and an attack is someone using it.

AttackHow it worksWhat stops it
ReconnaissanceScanning to learn what existsFewer open services, monitoring
Password attackGuessing or stealing loginsStrong passwords, lockouts
MalwareVirus needs a file, worm spreads alone, Trojan pretends to be usefulUpdates, antivirus
DoS / DDoSFlooding until it cannot serve othersFiltering, rate limits
On-pathSits in the middle and reads trafficEncryption: SSH, HTTPS

AAA: authentication (who are you?), authorization (what may you do?), accounting (what did you do?).

Tools: a firewall allows or blocks traffic. An ACL is an ordered rule list with an invisible "deny all" at the end. IDS alerts, IPS blocks. A VPN is an encrypted tunnel.

Protect a device: enable secret, SSH instead of Telnet, shut unused ports, keep backups, install updates.

Wi-Fi: WEP is broken. Use WPA2 or WPA3.

Remember: no single control is enough, so use several layers. This is called defense in depth.
